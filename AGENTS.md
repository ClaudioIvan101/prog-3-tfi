# Project work plan

Before planning or implementing project work, consult the user-designated principal evolving plan in `Plan_de_trabajo.pdf` and its local searchable companion `brain/Plans/Work-plan.md`. If unavailable or out of sync, ask for the current plan rather than infer its contents.

- The professor's assignment remains the requirements authority. The current plan takes planning precedence over earlier drafts and proposals; surface contradictions instead of silently resolving them.
- Plan tasks, target paths, and architectural decisions are not proof of implementation, completion, or permission to execute. Verify current repository evidence and obtain authorization for changes.
- Preserve the original PDF. Update its local copy and searchable snapshot only on explicit user instructions; record the source hash and date.
- The root PDF and all of `brain/Plans/` are private, Git-ignored local context. Do not stage, force-add, upload, or reproduce their contents in versioned documentation without explicit user authorization.

## Guided learning workflow

- The user builds the project manually while learning. Give one small practical step at a time, explain its purpose in this real-estate project, and wait for the user's result before advancing.
- Do not execute implementation or setup steps on the user's behalf unless explicitly requested. Permission to save learning preferences is not permission to configure the application.
- At the end of each practical block, ask the user to explain exactly what they did and why, in their own words. Review their explanation before continuing; ask at most one question at a time.
